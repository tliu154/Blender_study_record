# 实操 02：从一张图生成第一个 3D 模型

> 对应章节：[第 2 章 图生 3D](../docs/ch02_img2img3d.md) ｜ 预计耗时：60 分钟
> 状态：`[已完成]`

## 目标

用一张清晰的图，在 ComfyUI 里跑通图生 3D，得到一个可导出的网格模型。
任务分 A/B 档：**A 档真跑，B 档跑不动时看懂结构、记录卡点。**

## 前提

- [ ] ComfyUI 能启动，显存情况已知（[ch01_task](ch01_task.md)）
- [ ] 已安装一个图生 3D 节点包 + 对应模型（如 TripoSR 轻量方案）—— 按你选的包的说明安装
- [ ] 准备好一张输入图：主体单一、背景干净、清晰正视角（见 [ch02 2.4](../docs/ch02_img2img3d.md#c02-04)）

## 步骤

1. **准备输入图**：选一张符合 2.4 标准的图（如一个杯子、一个玩具、一个水果）。
   记录：主体是什么、背景是否干净、分辨率。

2. **搭最小工作流**（A 档）：按 [ch02 2.3 骨架](../docs/ch02_img2img3d.md#c02-03)，
   加载模型 → Load Image 载入图 → 图生 3D 节点 → 导出节点。
   - 节点名按你装的包为准，不必和教程完全一致

3. **运行生成**：Queue Prompt，观察耗时与显存占用。3D 生成通常比 2D 慢，耐心等。
   - A 档：记录耗时 ____ 秒，显存峰值 ____ GB
   - B 档（跑不动）：记录报错原文 ____，判断是显存不足 / 缺模型 / 节点问题

4. **查看结果**：把生成的网格在预览节点或导出后用查看器打开，转一圈看：
   - 正面像不像输入图？背面是否合理？
   - 有没有破面、缺块、法线异常？

5. **导出**：导出为 glb（[ch04](../docs/ch04_formats.md) 会详解格式），记下文件路径与大小。

6. **对比实验**：换一张**质量明显更差**的图（模糊/多主体），同样的参数再生成一次，对比结果差异。

## 验收标准

- [ ] A 档：成功生成一个可导出的 3D 网格，并转圈检查过
- [ ] B 档：说清卡在哪一步、为什么跑不动
- [ ] 记录了好图 vs 差图的结果差异，验证「输入图决定上限」
- [ ] 导出了 glb 文件

## 改一改会怎样（小实验）

| 改动 | 预期现象 | 为什么 |
|---|---|---|
| 换一张背景杂乱的图 | 结果质量下降/混入背景 | 输入图是质量上限，见 ch02 2.4 |
| 换更高质量档位（若有） | 更慢、更精细 | 质量与耗时/显存权衡，见 ch02 2.2 |
| 用多视图输入（若支持） | 背面更合理 | 多视角减少脑补，见 ch02 2.1 |

## 常见问题

- 显存爆了 → 换更轻量的方案（TripoSR）、降面数，或参考 [ComfyUI 性能篇](https://github.com/tliu154/ComfyUI_study_record/blob/main/06_ecosystem/docs/ch26_performance.md)
- 找不到 3D 节点 → 确认节点包已装、ComfyUI 已重启（[主仓库 ch24](https://github.com/tliu154/ComfyUI_study_record/blob/main/06_ecosystem/docs/ch24_manager.md)）
- 生成的模型破面/法线乱 → 正常，去 Blender 修（[ch05](../docs/ch05_handoff.md) + [ch08](../../02_blender_basics/docs/ch08_mesh_cleanup.md)）
- 其它 → [附录 C 故障排查](../../90_appendix/docs/appC_troubleshooting.md)
